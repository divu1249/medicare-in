# MediGuard â€” Proposed Database Schema

This is a proposed first migration, not an assertion that tables already exist. Use UUID primary keys, UTC `timestamptz` for instants, and explicit timezone identifiers for local scheduling.

## Core tables

### `profiles`
- `id uuid primary key references auth.users(id) on delete cascade`
- `display_name text`
- `timezone text not null default 'Asia/Kolkata'`
- `locale text not null default 'en'`
- `created_at`, `updated_at timestamptz not null`
- No clinical profile or clinician-verification claim.

### `emergency_contacts`
- `id uuid primary key`
- `user_id uuid not null references auth.users(id)`
- `display_name text not null`
- `relationship_label text`
- `phone_e164 text not null`
- `allow_sms_link boolean not null default false`
- `created_at`, `updated_at timestamptz not null`
- Consent/escalation settings should be separate, explicit, and revocable.

### `medications`
- `id uuid primary key`
- `user_id uuid not null references auth.users(id)`
- `display_name text not null`
- `strength_text text` and `form_text text` (user-entered strings; do not parse into clinical recommendations)
- `entry_source text not null check (entry_source in ('manual','ocr_confirmed'))`
- `label text not null default 'User-entered'`
- `archived_at timestamptz`
- `created_at`, `updated_at timestamptz not null`
- Do not hard-delete when dose history exists.

### `medication_schedule_versions`
- `id uuid primary key`
- `medication_id uuid not null references medications(id)`
- `user_id uuid not null references auth.users(id)`
- `version integer not null`
- `schedule_payload jsonb not null` (validated schema; user-confirmed values only)
- `timezone text not null`
- `effective_from timestamptz not null`
- `effective_until timestamptz`
- `user_confirmed_at timestamptz not null`
- `created_at timestamptz not null`
- `unique(medication_id, version)`
- Append new versions instead of overwriting prior instructions.

### `dose_events`
- `id uuid primary key`
- `user_id uuid not null references auth.users(id)`
- `medication_id uuid not null references medications(id)`
- `schedule_version_id uuid references medication_schedule_versions(id)`
- `scheduled_for timestamptz not null`
- `timezone text not null`
- `status text not null check (status in ('scheduled','acknowledged','reported_taken','skipped','missed','cancelled'))`
- `snoozed_until timestamptz`
- `reported_taken_at timestamptz`
- `verification jsonb` nullable (experimental unverified observation only; no images)
- `created_at`, `updated_at timestamptz not null`
- Unique idempotency key/constraint based on schedule version and occurrence identity to prevent duplicate generation.

### `dose_event_history`
- `id uuid primary key`
- `dose_event_id uuid not null references dose_events(id)`
- `user_id uuid not null references auth.users(id)`
- `previous_status text`, `new_status text not null`
- `actor text not null check (actor in ('user','system'))`
- `reason text`
- `created_at timestamptz not null`
- Append-only from the application perspective; never expose update/delete to normal clients.

### `refill_events`
- `id uuid primary key`
- `user_id uuid not null references auth.users(id)`
- `medication_id uuid not null references medications(id)`
- `quantity_delta numeric`
- `event_type text not null check (event_type in ('stock_added','stock_adjusted','refill_reminder'))`
- `occurred_at timestamptz not null`
- `notes text`
- Avoid assuming dose quantity or calculating clinical changes.

## Later tables
- `caregiver_access_grants`: patient, caregiver identity, explicit scopes, expiry, accepted/revoked timestamps, audit metadata.
- `notification_attempts`: dose event, channel, attempt state, timestamps, non-sensitive failure code; never treat delivery/open as a dose action.
- `knowledge_sources`: source organization/title/reference/jurisdiction/retrieval date/trust metadata.
- `knowledge_item_versions`: content, source metadata, version, reviewer, status, review timestamps.
- `content_packages`: jurisdiction, locale, version, content hash, publication identity, status, created/published timestamps.

## RLS requirements
- Enable RLS on every user-owned table.
- Patient-owned rows: `user_id = auth.uid()` for select/insert/update; restrict deletes and prefer archive.
- Schedule versions must be owned by the same user as the medication; enforce via transaction/RPC/trigger and tests, not only UI.
- Dose events must reference medications owned by the same user.
- `dose_event_history` should be readable only by the owning user and insertable only through a controlled function/transaction; ordinary clients cannot update/delete history.
- No public access to patient data. Caregiver access is not implicit and must not be added until scoped grants are implemented and tested.
- Content package publication should be writable only by a dedicated authorized reviewer/service workflow, not normal authenticated users.
- Add indexes for `(user_id, scheduled_for)`, `(user_id, archived_at)`, and relevant foreign keys.

## Retention and deletion
Define a documented account deletion/export process before production. Preserve history when archiving medications. Deletion semantics and backups must be explained to users; legal requirements remain unverified.

# MediGuard â€” API and Service Contract

## Approach
Use the Supabase JS client for ordinary authenticated CRUD protected by RLS. Use database functions or Edge Functions only where a transaction, trusted scheduling, publication, or privileged operation is needed. Do not create a generic service-role proxy.

## Client services (planned)
- `medications.listActive()`
- `medications.create(input)` â€” user-entered fields only; never infer schedule.
- `medications.update(id, patch)`
- `medications.archive(id)` â€” preserve history.
- `medications.createScheduleVersion(id, confirmedSchedule)`
- `doseEvents.list(range)`
- `doseEvents.acknowledge(id)`
- `doseEvents.reportTaken(id, source='manual')`
- `doseEvents.skip(id, reason?)`
- `doseEvents.snooze(id, until)`
- `emergencyContacts.list/create/update/delete`
- `contentPackages.getManifest(jurisdiction, locale)`
- `contentPackages.download(version)` â€” verify expected hash before storing.

## Dose transition contract
Canonical states: `scheduled`, `acknowledged`, `reported_taken`, `skipped`, `missed`, `cancelled`. Snooze is a separate timestamp. Notification open/dismiss events do not transition a dose.

Suggested allowed transitions:
- `scheduled â†’ acknowledged | reported_taken | skipped | missed | cancelled`
- `acknowledged â†’ reported_taken | skipped | missed | cancelled`
- `missed â†’ reported_taken` only if the product explicitly permits late self-report and the history captures it; otherwise require a correction workflow.
- `reported_taken`, `skipped`, `cancelled` are terminal in the MVP; corrections should be explicit, audited events rather than silent overwrites.
- `missed` is set by a trusted server process only after a documented grace rule. Do not infer that a person did or did not ingest medication.

Every transition writes `dose_event_history` atomically with the current state update. Retry-safe calls use idempotency keys or compare-and-set semantics.

## Error envelope
Return stable, non-clinical error codes such as:
- `UNAUTHENTICATED`
- `FORBIDDEN`
- `VALIDATION_ERROR`
- `NOT_FOUND`
- `CONFLICT`
- `RATE_LIMITED`
- `TEMPORARY_UNAVAILABLE`

Do not include tokens, full medical payloads, or internal secrets in errors/logs.

## Reminders
- Browser/in-app notifications are best-effort and platform-dependent.
- A notification attempt is not proof of delivery, opening, acknowledgement, or ingestion.
- Missed marking is server-side, idempotent, and based on an explicitly documented threshold; do not send clinical advice in escalation messages.
- Caregiver notifications are out of MVP; do not send to a contact without a future accepted grant and explicit scope/consent.

## Offline emergency package
Manifest fields: `package_id`, `jurisdiction`, `locale`, `version`, `published_at`, `content_hash`, `review_status`, `items[]`.
Each item requires: `item_id`, `title`, `body`, `source_organization`, `source_title`, `source_reference`, `publication_or_revision_date`, `retrieved_at`, `jurisdiction`, `version`, `review_status`, `reviewer_id`.
Only packages marked published/approved by the controlled publisher are installable. Validate schema and hash before replacing the last known-good package. Never let an update failure erase the working offline package.

## Emergency contact actions
`tel:` and `sms:` links open the corresponding device application. UI must state that the user still needs to place/send the call/message. Never report that a call was placed or help dispatched.

# MediGuard â€” Architecture

## Decision record
- **Frontend:** Existing React 18 + TypeScript + Vite app under `project/`; preserve existing UI and migrate incrementally.
- **Backend:** Supabase Auth + PostgreSQL + Row Level Security (RLS) + Edge Functions.
- **Offline store:** IndexedDB for approved content packages and minimal emergency contact data; service worker for app shell/static assets.
- **No separate Node/FastAPI server in the MVP.** Reconsider only if a demonstrated requirement cannot be met safely with Supabase.
- **AI:** No AI-generated clinical guidance in the MVP. A later audit workflow may flag source conflicts for human review.

## Logical components
1. **React UI:** routes and components; forms validate inputs but are not the security boundary.
2. **Domain services:** typed modules for medications, dose events, emergency contacts, and content packages. Avoid making `DataContext` a monolithic backend client.
3. **Supabase client:** browser-safe URL + anon/publishable key only; user JWT is managed by Supabase Auth.
4. **Postgres + RLS:** durable user-owned records; every table exposed to the client has explicit grants and policies.
5. **Edge Functions / scheduled job:** privileged or trusted workflows only, with strict authentication, authorization, idempotency, rate limits, and minimal logs.
6. **Offline emergency library:** previously downloaded, human-approved, versioned package; no network/LLM dependency for reading it.
7. **Content governance (later):** source registry â†’ automated checks/flags â†’ human review â†’ authorized publication â†’ signed/hashed package.

## Data flow
- User signs in â†’ Supabase Auth session â†’ client queries tables through RLS.
- User creates medication/schedule â†’ validated service â†’ RLS-protected rows.
- Scheduler materializes dose events idempotently for a bounded future horizon; local UI notifications are best-effort, not guaranteed background alarms.
- User explicitly reports taken/skipped â†’ append audit event and update current state in a transaction/RPC or Edge Function where needed.
- Emergency package is fetched while online, integrity-checked, stored in IndexedDB, then rendered offline.
- Contact links open device dialer/messaging app; the app does not send or claim dispatch itself.

## Suggested frontend organization
```text
project/src/
  lib/supabase.ts
  services/
    medications.ts
    doseEvents.ts
    emergencyContacts.ts
    contentPackages.ts
  types/
    domain.ts
  context/
    AuthContext.tsx
    DataContext.tsx   # temporary UI adapter; gradually slim down
  features/
    medications/
    dose-history/
    emergency/
    library/
  hooks/
  components/
```

## Migration strategy
1. Add architecture and safety docs before changing runtime behavior.
2. Introduce canonical domain types and explicit mapping from legacy localStorage/demo types.
3. Add Supabase schema, RLS, and policies before wiring production reads/writes.
4. Add auth/profile and core medication CRUD.
5. Add immutable schedule versions and dose event history.
6. Add offline package manifest, integrity validation, and reviewed-content metadata.
7. Migrate screens feature-by-feature; remove mock data only when each screen has a verified replacement.
8. Add automated tests and a staging review before enabling reminders or user data migration.

## Operational constraints
- `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` (or publishable key) are public client configuration, not secrets.
- Never put a Supabase service-role key in Vite variables or client bundles.
- Supabase Edge Functions must verify caller identity and authorization; service-role access bypasses RLS and must be narrowly scoped.
- Client-side timers and browser notifications cannot guarantee delivery while a browser/PWA is closed. Do not market them as guaranteed medication alarms.
- Package hashes detect accidental/tampered bytes only when compared to a trusted expected hash; they do not prove reviewer identity. Publication authorization and transport must be controlled.

# MediGuard â€” Product Specification

**Status:** Draft v1  
**Primary jurisdiction:** India (`IN`)  
**Default locale:** `en`  
**Default timezone:** `Asia/Kolkata`  
**Product class:** Medication-adherence and offline emergency-information helper; not a clinical system.

## Purpose
Help a person follow their own prescribed medication schedule, keep a self-reported dose history, access reviewed emergency-information packages offline, and optionally share bounded missed-dose alerts with an explicitly authorized caregiver.

## Non-goals
MediGuard is not a clinician, pharmacist, diagnostic tool, emergency dispatcher, medication recommender, or proof of ingestion. No clinician-verification workflow is part of the MVP.

## Safety requirements
- **SAFE-1 â€” No clinical decisions:** Never diagnose, prescribe, recommend a medication, or tell a user to start, stop, or change medication or dosage.
- **SAFE-2 â€” Schedule provenance:** Schedules come from user entry or OCR followed by user confirmation. The system never infers a schedule. Ambiguous instructions remain as entered and are flagged to ask a clinician/pharmacist.
- **SAFE-3 â€” Explicit dose action:** Opening or dismissing a notification never changes dose status. Only an explicit user action can report a dose taken, skipped, or otherwise acknowledged.
- **SAFE-4 â€” Canonical dose states:** `scheduled`, `acknowledged`, `reported_taken`, `skipped`, `missed`, `cancelled`. Snooze is `snoozed_until`, not a status. Camera output is a separate `verification` observation.
- **SAFE-5 â€” User-entered label:** User-entered medication information must be labeled â€œUser-enteredâ€; MVP must not claim clinician verification.
- **SAFE-6 â€” Camera limits:** Camera analysis is optional and experimental. Store an unverified observation and confidence only; never claim ingestion confirmed. Keep frames on-device and do not store them. Manual reporting always remains available.
- **SAFE-7 â€” Bounded escalation:** Escalation changes who is informed, not medical instructions. It is opt-in, bounded, visible, and revocable.
- **SAFE-8 â€” Approved content only:** User-facing emergency guidance comes only from published, human-approved, versioned, sourced packages. AI output is never directly shown as guidance.
- **SAFE-9 â€” Content provenance:** Every published item records source organization, title, URL/reference, publication/revision date, retrieval date, jurisdiction, version, review status, and reviewer.
- **SAFE-10 â€” Conflict handling:** Conflicting, outdated, or unsupported content is routed to human review. The system never chooses a clinical recommendation.
- **SAFE-11 â€” Offline access:** After the app and package have loaded once, the emergency library, emergency contacts card, and call/message links must work offline without login, LLM, or paid API access.
- **SAFE-12 â€” No dispatch claims:** `tel:` and `sms:` links merely open the device app. MediGuard must never claim that help was dispatched.
- **SAFE-13 â€” Facility uncertainty:** Facility information is approximate/unverified unless supplied by a trusted provider. Never invent opening hours, capacity, or travel time.
- **SAFE-14 â€” Privacy:** Medical data is sensitive. Obtain consent before caregiver sharing or external AI/provider processing. Never log PHI, access tokens, or secrets.

## MVP scope
1. Account/profile and timezone.
2. Emergency contacts.
3. Medication create/edit/archive; schedule versions; stock and refill events.
4. Dose events and self-reported dose history.
5. Reminder UI and in-app/browser notifications while supported; server-side missed marking only after explicit, documented rules.
6. Baseline offline emergency library built from reviewed content packages.
7. Client-side Tesseract OCR that requires user review and confirmation.
8. Experimental camera motion-difference prototype, isolated from dose status.
9. Client-side PDF report generated from authorized API data.

## Later / out of MVP
- Caregiver invitations and scoped grants; web push and bounded escalation.
- Versioned IndexedDB package updates.
- Document upload management.
- Facility-provider integration/manual location fallback.
- Knowledge-base audit pipeline and reviewer publication console.
- Server OCR, semantic search, smart pillbox, computer-vision classifier.

## Existing UI reconciliation
- â€œAI Health Advisorâ€ becomes Library Q&A over approved content only; no generative clinical answers in MVP.
- Labs/Visits remain clearly labeled demo content until persistence and provenance exist.
- Inventory/refill lives on medication and `refill_events`.
- Reports use jsPDF in the client, populated from API responses.
- Hospital directory stays clearly marked â€œSampleâ€ until a real provider is integrated.

## Metrics
Reported adherence for a period is:
`reported_taken / (reported_taken + skipped + missed)` across resolved dose events in that period. Label it **self-reported**. Exclude `scheduled`, `acknowledged`, and `cancelled` from the denominator.

## Terminology
A **dose event** is one scheduled occurrence at a local date/time, stored with a timezone-aware timestamp. A **content package** is a versioned JSON bundle of approved item versions for a jurisdiction and locale, identified by a cryptographic hash. A hash alone does not establish reviewer identity or authorization.

# MediGuard â€” Security and Privacy Baseline

## Threat model
Sensitive assets include medication names/schedules, dose history, emergency contacts, account identifiers, access tokens, and optional caregiver relationships. Threats include cross-account access, leaked client secrets, overbroad caregiver access, logs containing health data, compromised dependencies, malicious package updates, and accidental loss of offline emergency information.

## Required controls
1. Enable RLS on every user-owned table and test both allowed and denied cross-user access.
2. Keep only Supabase URL and anon/publishable key in the browser. Never expose service-role keys or other secrets in `VITE_*`, source control, logs, or browser storage.
3. Validate all input server-side where security matters. Client-side validation improves UX but is not authorization.
4. Use least privilege for Edge Functions and publication workflows; authenticate caller and authorize the requested record/scope.
5. Avoid logging request bodies or medical data. Redact authorization headers, tokens, phone numbers, and user-provided notes.
6. Require explicit, revocable consent before any future caregiver sharing or external AI/provider processing.
7. Do not upload camera frames. Camera analysis is optional, on-device, and returns only a separately stored unverified observation.
8. Do not persist OCR source images unless a separately reviewed requirement is added; user must confirm extracted text.
9. Treat all medication entries as â€œUser-entered.â€ No clinician verification claim in MVP.
10. Keep approved emergency content available offline; validate package schema/hash and preserve last known-good package on failed updates.
11. Apply dependency updates, secret scanning, and lockfile review. Verify `.env` is ignored and no secrets have been committed.
12. Implement account export/deletion and explain retention before production use.

## Authentication and session
- Use Supabase Auth-supported session handling; do not build a custom token store.
- Sign-out should clear authenticated application state while leaving only the minimal offline emergency package/contact data that the user knowingly opted to retain.
- Avoid caching authenticated API responses in the service worker cache.
- Do not place private data in URL query strings.

## Logging and analytics
- Log operation identifiers, coarse outcomes, and non-sensitive error codes only.
- Never log PHI, medication schedules, access tokens, service keys, raw OCR text, camera frames, or emergency contact details.
- Analytics must be optional and must not contain health data by default.

## Release gate
Before any public/real-user deployment, review RLS policies, test account isolation, inspect build output for secrets, test offline access, test export/deletion, review third-party data flows, and obtain appropriate privacy/legal review. Compliance status is currently unverified; do not claim regulatory compliance.

# MediGuard â€” AI and Knowledge Audit Governance

## MVP boundary
No LLM-generated medical guidance is shown to users. The Library Q&A may retrieve or display only approved, versioned content items. If a question cannot be answered from approved items, say the library does not contain a reviewed answer and direct the user to a qualified professional or local emergency service as appropriateâ€”without inventing instructions.

## Future audit pipeline
1. **Ingest metadata:** source organization, title, URL/reference, jurisdiction, publication/revision date, retrieval date, content type, and permitted-use notes.
2. **Validate:** schema, URL availability where feasible, required provenance, jurisdiction, dates, version, and source allow-list.
3. **Compare:** detect possible conflicts, stale versions, missing citations, unsupported claims, and duplicate/near-duplicate items.
4. **Flag, never decide:** AI or automated checks may produce internal flags with evidence and confidence; they must not select between conflicting clinical recommendations or publish content.
5. **Human review:** authorized reviewer checks source and content, records identity, decision, rationale, and review timestamp.
6. **Publish:** controlled workflow creates an immutable version and package manifest; only approved versions enter user-facing packages.
7. **Distribute:** client validates schema and trusted hash/signature and keeps the previous package if the update fails.
8. **Audit:** preserve version history and who/what approved each publication.

## Required item metadata
`source_organization`, `source_title`, `source_reference`, `publication_or_revision_date`, `retrieved_at`, `jurisdiction`, `locale`, `version`, `review_status`, `reviewer_id`, `reviewed_at`, `content_hash`.

## Review statuses
Suggested values: `draft`, `needs_review`, `approved`, `rejected`, `superseded`, `withdrawn`. Only `approved` and currently published versions are user-visible. Withdrawal/supersession must propagate in the next package update and be clearly handled offline.

## Prompt-injection and source safety
Treat source pages, uploaded documents, OCR text, and retrieved content as untrusted dataâ€”not instructions to the AI pipeline. Never allow source text to change system policy, invoke tools, expose secrets, or publish itself. Separate content from metadata and sanitize rendered HTML.

## Clinical-content policy
Use authoritative, jurisdiction-appropriate sources selected by a qualified reviewer. Do not fabricate sources or dates. Do not publish first-aid/CPR/medication-specific material until a human reviewer confirms the exact content, jurisdiction, and currency. Conflicts and uncertain evidence remain blocked for review.

import type { Medication, DoseRecord, RefillEvent } from '@/types';

export function todayISO(offsetDays = 0): string {
  const d = new Date();
  d.setDate(d.getDate() + offsetDays);
  return d.toISOString().split('T')[0];
}

export function formatDate(iso: string): string {
  if (!iso) return 'Not provided';
  const d = new Date(iso + (iso.length === 10 ? 'T00:00:00' : ''));
  if (isNaN(d.getTime())) return iso;
  return d.toLocaleDateString(undefined, { year: 'numeric', month: 'short', day: 'numeric' });
}

export function formatTime(t: string): string {
  if (!t) return '';
  const [h, m] = t.split(':');
  const hour = parseInt(h, 10);
  const ampm = hour >= 12 ? 'PM' : 'AM';
  const h12 = hour % 12 || 12;
  return `${h12}:${m} ${ampm}`;
}

export function daysBetween(a: string, b: string): number {
  const d1 = new Date(a + 'T00:00:00').getTime();
  const d2 = new Date(b + 'T00:00:00').getTime();
  return Math.round((d2 - d1) / 86400000);
}

export function estimateSupply(med: Medication): { daysRemaining: number; runOutDate: string } | null {
  const dosesPerDay = med.times.length || 1;
  const usedPerDay = med.quantityPerDose * dosesPerDay;
  if (usedPerDay <= 0 || med.quantity <= 0) return null;
  const daysRemaining = Math.floor(med.quantity / usedPerDay);
  const runOut = new Date();
  runOut.setDate(runOut.getDate() + daysRemaining);
  return { daysRemaining, runOutDate: runOut.toISOString().split('T')[0] };
}

export function isLowStock(med: Medication): boolean {
  return med.quantity <= med.lowStockThreshold;
}

export function getAdherenceStats(doses: DoseRecord[]): { rate: number; taken: number; total: number; missed: number; skipped: number } {
  const past = doses.filter((d) => d.status !== 'scheduled' || d.scheduledDate < todayISO());
  const total = past.length || 1;
  const taken = past.filter((d) => d.status === 'taken').length;
  const missed = past.filter((d) => d.status === 'missed').length;
  const skipped = past.filter((d) => d.status === 'skipped').length;
  return { rate: Math.round((taken / total) * 100), taken, total, missed, skipped };
}

export function getTodayDoses(doses: DoseRecord[], medications: Medication[]): DoseRecord[] {
  const today = todayISO();
  const medIds = new Set(medications.map((m) => m.id));
  return doses
    .filter((d) => d.scheduledDate === today && medIds.has(d.medicationId))
    .sort((a, b) => a.scheduledTime.localeCompare(b.scheduledTime));
}

export function getRefillAlerts(medications: Medication[]): { med: Medication; daysRemaining: number; runOutDate: string }[] {
  const alerts: { med: Medication; daysRemaining: number; runOutDate: string }[] = [];
  medications.forEach((med) => {
    if (isLowStock(med)) {
      const est = estimateSupply(med);
      alerts.push({ med, daysRemaining: est?.daysRemaining ?? 0, runOutDate: est?.runOutDate ?? 'Unknown' });
    }
  });
  return alerts.sort((a, b) => a.daysRemaining - b.daysRemaining);
}

export function uid(prefix = ''): string {
  return `${prefix}${Date.now()}-${Math.random().toString(36).slice(2, 8)}`;
}

export function getDosesForDate(doses: DoseRecord[], medications: Medication[], date: string): DoseRecord[] {
  const medIds = new Set(medications.map((m) => m.id));
  return doses
    .filter((d) => d.scheduledDate === date && medIds.has(d.medicationId))
    .sort((a, b) => a.scheduledTime.localeCompare(b.scheduledTime));
}

export function ensureTodayDoses(doses: DoseRecord[], medications: Medication[]): DoseRecord[] {
  const today = todayISO();
  const existing = new Set(doses.filter((d) => d.scheduledDate === today).map((d) => `${d.medicationId}-${d.scheduledTime}`));
  const newDoses: DoseRecord[] = [];
  medications.forEach((med) => {
    med.times.forEach((time) => {
      const key = `${med.id}-${time}`;
      if (!existing.has(key)) {
        newDoses.push({
          id: uid('dose-'),
          medicationId: med.id,
          medicationName: med.name,
          scheduledDate: today,
          scheduledTime: time,
          dosage: `${med.dosage} ${med.unit}`,
          status: 'scheduled',
          confirmedAt: null,
          monitoringStatus: 'scheduled',
          source: 'manual',
          note: '',
        });
      }
    });
  });
  return newDoses.length > 0 ? [...doses, ...newDoses] : doses;
}

export function refillHistoryForMed(refills: RefillEvent[], medId: string): RefillEvent[] {
  return refills.filter((r) => r.medicationId === medId).sort((a, b) => b.date.localeCompare(a.date));
}

import type {

function load<T>(key: string, fallback: T): T {
  try {
    const raw = localStorage.getItem(key);
    return raw ? (JSON.parse(raw) as T) : fallback;
  } catch {
    return fallback;
  }
}

function save<T>(key: string, value: T) {
  try {
    localStorage.setItem(key, JSON.stringify(value));
  } catch {
    /* storage may be full or blocked */
  }
}

export interface DataContextValue {
  profile: PatientProfile;
  setProfile: (p: PatientProfile) => void;
  medications: Medication[];
  addMedication: (m: Medication) => void;
  updateMedication: (m: Medication) => void;
  deleteMedication: (id: string) => void;
  doses: DoseRecord[];
  addDose: (d: DoseRecord) => void;
  updateDose: (id: string, patch: Partial<DoseRecord>) => void;
  setDoseStatus: (id: string, status: DoseStatus, source?: DoseRecord['source']) => void;
  refills: RefillEvent[];
  addRefill: (r: RefillEvent) => void;
  labs: LabReport[];
  visits: VisitRecord[];
  reports: MedicalReport[];
  addReport: (r: MedicalReport) => void;
  bookmarks: Bookmark[];
  toggleBookmark: (articleId: string) => void;
  chat: ChatMessage[];
  addChatMessage: (m: ChatMessage) => void;
  clearChat: () => void;
  settings: AppSettings;
  updateSettings: (patch: Partial<AppSettings>) => void;
  resetDemoData: () => void;
}

const DataContext = createContext<DataContextValue | null>(null);

export function DataProvider({ children }: { children: ReactNode }) {
  const [profile, setProfileState] = useState<PatientProfile>(() => load(KEYS.profile, defaultProfile));
  const [medications, setMedications] = useState<Medication[]>(() => load(KEYS.medications, defaultMedications));
  const [doses, setDoses] = useState<DoseRecord[]>(() => load(KEYS.doses, defaultDoses));
  const [refills, setRefills] = useState<RefillEvent[]>(() => load(KEYS.refills, defaultRefills));
  const [labs] = useState<LabReport[]>(() => load(KEYS.labs, defaultLabReports));
  const [visits] = useState<VisitRecord[]>(() => load(KEYS.visits, defaultVisits));
  const [reports, setReports] = useState<MedicalReport[]>(() => load(KEYS.reports, defaultReports));
  const [bookmarks, setBookmarks] = useState<Bookmark[]>(() => load(KEYS.bookmarks, []));
  const [chat, setChat] = useState<ChatMessage[]>(() => load(KEYS.chat, []));
  const [settings, setSettings] = useState<AppSettings>(() => ({ ...defaultSettings, ...load(KEYS.settings, {}) as Partial<AppSettings> }));

  useEffect(() => save(KEYS.profile, profile), [profile]);
  useEffect(() => save(KEYS.medications, medications), [medications]);
  useEffect(() => save(KEYS.doses, doses), [doses]);
  useEffect(() => save(KEYS.refills, refills), [refills]);
  useEffect(() => save(KEYS.reports, reports), [reports]);
  useEffect(() => save(KEYS.bookmarks, bookmarks), [bookmarks]);
  useEffect(() => save(KEYS.chat, chat), [chat]);
  useEffect(() => save(KEYS.settings, settings), [settings]);

  const setProfile = useCallback((p: PatientProfile) => setProfileState(p), []);

  const addMedication = useCallback((m: Medication) => setMedications((prev) => [...prev, m]), []);
  const updateMedication = useCallback((m: Medication) => setMedications((prev) => prev.map((x) => (x.id === m.id ? m : x))), []);
  const deleteMedication = useCallback((id: string) => {
    setMedications((prev) => prev.filter((x) => x.id !== id));
    setDoses((prev) => prev.filter((d) => d.medicationId !== id));
  }, []);

  const addDose = useCallback((d: DoseRecord) => setDoses((prev) => [...prev, d]), []);
  const updateDose = useCallback((id: string, patch: Partial<DoseRecord>) =>
    setDoses((prev) => prev.map((d) => (d.id === id ? { ...d, ...patch } : d))), []);
  const setDoseStatus = useCallback((id: string, status: DoseStatus, source: DoseRecord['source'] = 'manual') =>
    setDoses((prev) => prev.map((d) => (d.id === id ? { ...d, status, source, confirmedAt: status === 'taken' ? new Date().toISOString() : null } : d))), []);

  const addRefill = useCallback((r: RefillEvent) => setRefills((prev) => [...prev, r]), []);

  const addReport = useCallback((r: MedicalReport) => setReports((prev) => [r, ...prev]), []);

  const toggleBookmark = useCallback((articleId: string) =>
    setBookmarks((prev) => {
      const exists = prev.find((b) => b.articleId === articleId);
      return exists ? prev.filter((b) => b.articleId !== articleId) : [...prev, { id: `bm-${Date.now()}`, articleId, savedDate: new Date().toISOString() }];
    }), []);

  const addChatMessage = useCallback((m: ChatMessage) => setChat((prev) => [...prev, m]), []);
  const clearChat = useCallback(() => setChat([]), []);

  const updateSettings = useCallback((patch: Partial<AppSettings>) => {
    setSettings((prev) => {
      const next = { ...prev, ...patch };
      if (patch.theme) setTheme(patch.theme);
      return next;
    });
  }, []);

  const resetDemoData = useCallback(() => {
    Object.values(KEYS).forEach((k) => localStorage.removeItem(k));
    setProfileState(defaultProfile);
    setMedications(defaultMedications);
    setDoses(defaultDoses);
    setRefills(defaultRefills);
    setReports(defaultReports);
    setBookmarks([]);
    setChat([]);
    setSettings(defaultSettings);
    setTheme(defaultSettings.theme);
  }, []);

  const value: DataContextValue = {
    profile,
    setProfile,
    medications,
    addMedication,
    updateMedication,
    deleteMedication,
    doses,
    addDose,
    updateDose,
    setDoseStatus,
    refills,
    addRefill,
    labs,
    visits,
    reports,
    addReport,
    bookmarks,
    toggleBookmark,
    chat,
    addChatMessage,
    clearChat,
    settings,
    updateSettings,
    resetDemoData,
  };

  return <DataContext.Provider value={value}>{children}</DataContext.Provider>;
}

export function useData() {
  const ctx = useContext(DataContext);
  if (!ctx) throw new Error('useData must be used within DataProvider');
  return ctx;
}

function OcrImport({ onExtract }: { onExtract: (text: string) => void }) {
  const [image, setImage] = useState<string | null>(null);
  const [extracted, setExtracted] = useState('');
  const [processing, setProcessing] = useState(false);
  const [error, setError] = useState('');
  const notify = useToast();

  async function handleFile(file: File) {
    setError('');
    setExtracted('');
    const reader = new FileReader();
    reader.onload = () => setImage(reader.result as string);
    reader.readAsDataURL(file);
  }

  async function runOcr() {
    if (!image) return;
    setProcessing(true);
    setError('');
    try {
      const { default: Tesseract } = await import('tesseract.js');
      const result = await Tesseract.recognize(image, 'eng');
      setExtracted(result.data.text);
      onExtract(result.data.text);
      notify('OCR extraction complete. Please review the text carefully.', 'success');
    } catch {
      setError('OCR processing failed. You can still enter medication details manually.');
      notify('OCR failed. Please enter details manually.', 'error');
    } finally {
      setProcessing(false);
    }
  }

  return (
    <div className="space-y-4">
      <div className="rounded-xl bg-warning-50 p-3 text-xs text-warning-700 dark:bg-warning-700/10 dark:text-warning-400">
        <AlertCircle className="mb-1 inline h-4 w-4" /> OCR may misread medicine names, strengths and instructions. Always verify extracted text against your original prescription before saving.
      </div>
      <div>
        <label className="label">Upload prescription or medicine label image</label>
        <input type="file" accept="image/*" className="input" onChange={(e) => e.target.files?.[0] && handleFile(e.target.files[0])} />
      </div>
      {image && (
        <div>
          <img src={image} alt="Uploaded" className="max-h-48 rounded-xl border border-gray-200 dark:border-slate-700" />
          <button onClick={runOcr} disabled={processing} className="btn btn-primary mt-3">
            <ScanLine className="h-4 w-4" /> {processing ? 'Processing...' : 'Extract Text'}
          </button>
        </div>
      )}
      {error && <p className="text-sm text-error-500">{error}</p>}
      {extracted && (
        <div>
          <label className="label">Extracted Text (review and correct)</label>
          <textarea className="input" rows={6} value={extracted} onChange={(e) => { setExtracted(e.target.value); onExtract(e.target.value); }} />
        </div>
      )}
    </div>
  );
}

  const stopCamera = useCallback(() => {
    if (streamRef.current) {
      streamRef.current.getTracks().forEach((t) => t.stop());
      streamRef.current = null;
    }
    if (videoRef.current) videoRef.current.srcObject = null;

      clearInterval(motionTimerRef.current);

    }

  async function startCamera() {
    setCamState('requesting');
    try {
      const stream = await navigator.mediaDevices.getUserMedia({ video: true, audio: false });
      streamRef.current = stream;
      if (videoRef.current) {
        videoRef.current.srcObject = stream;
        await videoRef.current.play();
      }
      setCamState('active');
      setDemoMode(false);
      notify('Camera started. Monitoring is ready.', 'success');
    } catch (err) {

      if (e.name === 'NotAllowedError') {
        setCamState('denied');
        notify('Camera permission denied. Use Demo Mode or manual tracking.', 'warning');
      } else {
        setCamState('error');
        notify('Camera could not be started. ' + e.message, 'error');
      }
    }
  }

  function startMonitoring(doseId: string) {
    if (demoMode || camState !== 'active') {
      setDemoMode(true);
      setActiveDoseId(doseId);
      setMonitoringStatus('monitoring');
      notify('Demonstration Mode active. This simulates motion detection.', 'info');
      runDemoSimulation();
      return;
    }
    setActiveDoseId(doseId);
    setMonitoringStatus('monitoring');
    updateDose(doseId, { monitoringStatus: 'monitoring' });
    startMotionDetection(doseId);
  }

  function startMotionDetection(doseId: string) {
    setMonitoringStatus('waiting');
    updateDose(doseId, { monitoringStatus: 'waiting' });
    if (motionTimerRef.current) clearInterval(motionTimerRef.current);

    motionTimerRef.current = window.setInterval(() => {
      const video = videoRef.current;
      const canvas = motionCanvasRef.current;
      if (!video || !canvas || video.readyState !== 4) return;
      const ctx = canvas.getContext('2d');
      if (!ctx) return;
      canvas.width = 160;
      canvas.height = 120;
      ctx.drawImage(video, 0, 0, canvas.width, canvas.height);
      const current = ctx.getImageData(0, 0, canvas.width, canvas.height);

      if (prevFrameRef.current) {
        let diff = 0;
        const data = current.data;
        const prev = prevFrameRef.current.data;
        for (let i = 0; i < data.length; i += 4) {
          diff += Math.abs(data[i] - prev[i]) + Math.abs(data[i + 1] - prev[i + 1]) + Math.abs(data[i + 2] - prev[i + 2]);
        }
        const normalized = diff / (data.length / 4) / 765;
        setMotionScore(normalized);
        if (normalized > 0.06 && monitoringStatus === 'waiting') {
          setMonitoringStatus('movement_detected');
          updateDose(doseId, { monitoringStatus: 'movement_detected' });
          setShowConfirm(true);
          if (motionTimerRef.current) clearInterval(motionTimerRef.current);
        }
      }
      prevFrameRef.current = current;
    }, 500);
  }

  function runDemoSimulation() {
    setMonitoringStatus('waiting');
    setTimeout(() => {
      setMonitoringStatus('movement_detected');
      if (activeDoseId) updateDose(activeDoseId, { monitoringStatus: 'movement_detected' });
      setShowConfirm(true);
    }, 3500);
  }

  function confirmTaken() {
    if (activeDoseId) {
      updateDose(activeDoseId, { status: 'taken', monitoringStatus: 'confirmed', source: demoMode ? 'simulated' : 'camera', confirmedAt: new Date().toISOString() });
      notify('Dose confirmed as taken.', 'success');
    }
    setShowConfirm(false);
    setActiveDoseId(null);
    setMonitoringStatus('scheduled');
  }

  function confirmNotTaken() {
    if (activeDoseId) {
      updateDose(activeDoseId, { status: 'not_confirmed', monitoringStatus: 'not_confirmed', source: demoMode ? 'simulated' : 'camera' });
      notify('Dose marked as not taken. No dose doubling is advised.', 'info');
    }
    setShowConfirm(false);
    setActiveDoseId(null);
    setMonitoringStatus('scheduled');
  }

  const monitoringSessions = allDoses.filter((d) => d.source === 'camera' || d.source === 'simulated' || d.monitoringStatus !== 'scheduled').slice(-8).reverse();

  const statusInfo: Record<MonitoringStatus, { label: string; color: string }> = {
    scheduled: { label: 'Scheduled', color: 'text-gray-500' },
    monitoring: { label: 'Monitoring in Progress', color: 'text-secondary-500' },
    waiting: { label: 'Waiting for Movement', color: 'text-warning-500' },
    movement_detected: { label: 'Movement Detected', color: 'text-primary-500' },
    review: { label: 'Review Required', color: 'text-warning-500' },
    confirmed: { label: 'Patient Confirmed', color: 'text-success-500' },
    not_confirmed: { label: 'Not Confirmed', color: 'text-warning-500' },
    missed: { label: 'Missed Dose', color: 'text-error-500' },
  };

  return (
    <div>
      <PageHeader
        title="Camera-Assisted Dose Monitoring"
        subtitle="Detects possible medication-taking movement. Movement is never proof of ingestion â€” your confirmation is always required."
      />

      {/* Safety notices */}
      <div className="mb-6 grid gap-3 sm:grid-cols-2">
        <div className="flex items-start gap-2 rounded-xl bg-secondary-50 p-3 text-xs text-secondary-700 dark:bg-secondary-700/10 dark:text-secondary-400">
          <ShieldCheck className="mt-0.5 h-4 w-4 shrink-0" />
          <p>Camera frames are processed locally in your browser. No video is recorded, uploaded, or retained. Camera stops automatically when you leave this page.</p>
        </div>
        <div className="flex items-start gap-2 rounded-xl bg-warning-50 p-3 text-xs text-warning-700 dark:bg-warning-700/10 dark:text-warning-400">
          <AlertCircle className="mt-0.5 h-4 w-4 shrink-0" />
          <p>Motion detection cannot prove a medicine was swallowed. Lighting, camera angle, and other movements can affect accuracy. Always confirm manually.</p>
        </div>
      </div>

      <div className="grid gap-6 lg:grid-cols-2">
        {/* Camera preview */}
        <Card>
          <div className="mb-3 flex items-center justify-between">
            <SectionTitle>Camera Preview</SectionTitle>
            {camState === 'active' && (
              <Badge variant="error"><span className="h-2 w-2 animate-pulse rounded-full bg-error-500" /> Camera Active</Badge>
            )}
          </div>
          <div className="relative overflow-hidden rounded-xl bg-black aspect-video">
            <video ref={videoRef} className="h-full w-full object-cover" playsInline muted />
            <canvas ref={motionCanvasRef} className="hidden" />
            {camState !== 'active' && (
              <div className="absolute inset-0 flex flex-col items-center justify-center text-gray-400">
                <VideoOff className="h-12 w-12" />
                <p className="mt-2 text-sm">Camera is off</p>
              </div>
            )}
            {camState === 'active' && monitoringStatus !== 'scheduled' && (
              <div className="absolute bottom-3 left-3 rounded-lg bg-black/60 px-3 py-1.5 text-xs text-white">
                <Activity className="mr-1 inline h-3 w-3" />
                {statusInfo[monitoringStatus].label} {motionScore > 0 && `Â· Motion: ${(motionScore * 100).toFixed(1)}%`}
              </div>
            )}

          <div className="mt-4 flex flex-wrap gap-2">
